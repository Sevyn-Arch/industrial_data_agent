# 团队分工与开发过程文档

> 命题方：和利时企业命题 ｜ 项目名称：工业数据分析 Agent 系统 ｜ 文档类型：团队分工与开发过程

## 一、团队角色与职责分工

团队共 5 人，采用"一横一纵"的矩阵式协作：纵向按模块负责到底，横向通过接口契约与阶段评审对齐。

### 1.1 项目负责人兼后端集成（成员 A）

- **职责**：需求拆解与范围界定、总体架构与分层依赖设计、接口契约（统一结果结构）定义、各模块集成与联调、进度把控与风险预警、对外汇报；
- **主要产出**：需求说明与架构设计文档、模块集成与联调记录、阶段评审结论；
- **能力侧重**：系统设计、Python 工程化、跨模块问题定位。

### 1.2 前端交互开发（成员 B）

- **职责**：Streamlit 界面四个功能页签的设计与实现、交互流程编排、结果可视化呈现（指标卡、图表网格、执行时间线、结果表格）、上传与下载交互、界面异常兜底；
- **主要产出**：Web 界面主程序、交互设计说明、界面自测记录；
- **能力侧重**：Python 前端框架、信息层级设计、用户体验打磨。

### 1.3 Agent 核心开发（成员 C）

- **职责**：大模型客户端封装（重试、模型降级、双通道传输、密钥脱敏）、意图解析规则体系、代码生成提示词工程、生成代码静态校验接入与自动修复闭环、分析流程编排与历史记录；
- **主要产出**：大模型客户端、代码生成器、Agent 主控制器、提示词库与意图规则表；
- **能力侧重**：大模型应用开发、提示词工程、流程编排与异常处理。

### 1.4 数据分析算法开发（成员 D）

- **职责**：五大算法模块的设计与实现（基础统计、相关性、时滞、异常检测、机器学习建模）、算法参数与工程取值确定、图表工业可读性优化、结果口径统一；
- **主要产出**：算法库、算法说明（原理、参数、指标含义）、图表样式规范；
- **能力侧重**：统计与机器学习、pandas / scikit-learn、工业数据处理经验。

### 1.5 测试与文档交付（成员 E）

- **职责**：测试策略与用例设计、安全机制验证（危险代码拦截、路径越界、超时终止、密钥隔离）、端到端场景回归、缺陷跟踪与复测、交付文档与演示材料撰写；
- **主要产出**：测试用例集与自动化测试报告、安全验证清单、缺陷跟踪表、全套交付文档与汇报 PPT；
- **能力侧重**：测试设计、安全思维、技术文档写作。

## 二、项目开发排期与里程碑

项目周期 14 天，划分为 6 个阶段、6 个里程碑。

| 阶段 | 时间 | 主要工作 | 里程碑 |
| --- | --- | --- | --- |
| 阶段一：需求分析与方案设计 | 第 1–2 天 | 命题解读、场景调研、需求拆解与优先级排序；确定技术栈、目录结构、分层架构与接口契约（统一结果结构） | M1 需求与架构评审通过 |
| 阶段二：基础框架与算法库 | 第 3–6 天 | 搭建项目骨架与配置体系；实现数据读取与数据画像；完成基础统计、相关性、时滞、异常检测、机器学习五大算法模块 | M2 算法库单元测试全绿 |
| 阶段三：智能体核心开发 | 第 7–9 天 | 完成大模型客户端封装（重试、降级、双通道、脱敏）；实现八大意图解析、代码生成提示词与本地模板兜底；打通"生成—执行—修复"闭环 | M3 自然语言端到端跑通 |
| 阶段四：安全沙箱引擎 | 第 9–11 天 | 实现子进程隔离执行、AST 白名单校验、目录权限限制、超时与进程树终止、环境变量脱敏、结果与图表回收 | M4 安全验证用例全部通过 |
| 阶段五：报告生成与界面集成 | 第 11–13 天 | 实现事实优先的报告生成器（双通道、Markdown 与自包含 HTML 导出）；完成四页签界面与全流程集成 | M5 产品级界面可演示 |
| 阶段六：测试优化与交付 | 第 13–14 天 | 全量端到端回归、性能与易用性优化、文档与 PPT 撰写、演示脚本准备与预演 | M6 交付物齐备并完成预演 |

## 三、各阶段交付物与验收标准

| 阶段 | 交付物 | 验收标准 |
| --- | --- | --- |
| 一 | 需求说明、架构设计说明、目录与接口规范 | 需求条目可追溯到功能清单；接口契约经全体评审通过；技术方案无遗留争议项 |
| 二 | 项目骨架、配置体系、五大算法模块 | 每个算法模块可独立运行；正常输入返回统一结构结果、异常输入返回明确错误提示；算法库单元测试 100% 通过 |
| 三 | 大模型客户端、代码生成器、Agent 主控制器 | 有密钥时可生成并执行定制代码，无密钥时自动回落模板并完整出结果；意图识别在示例问题集上准确率满足验收要求 |
| 四 | 沙箱执行引擎、安全验证清单 | 危险导入、危险函数、魔术属性、无界循环、路径越界、文件删除、超时、密钥外泄等场景全部被正确拦截或受控终止 |
| 五 | 报告生成器、四页签 Web 界面 | 界面可完成"上传—提问—执行—查看结果—下载报告"全流程；报告含结论、指标、图表与建议四类要素且与执行事实一致 |
| 六 | 测试报告、交付文档、PPT 与演示脚本 | 全量自动化测试通过；文档与实现一致无夸大；演示 3 个场景无卡顿、无报错 |

## 四、关键开发节点记录

| 节点 | 时间 | 事件 | 影响与处置 |
| --- | --- | --- | --- |
| N1 | 第 2 天 | 架构评审中确定"分层依赖 + 统一结果结构"两条硬约束 | 后续所有模块禁止越层调用，接口返工量显著下降 |
| N2 | 第 4 天 | 发现 CSV 中文乱码与时间列被识别为文本 | 增加多编码自适应读取与时间字段抽样解析，数据画像准确率提升 |
| N3 | 第 5 天 | 中文图表出现方块乱码 | 增加绘图字体自动探测与负号显示修正，图表可读性达标 |
| N4 | 第 8 天 | 大模型调用偶发超时、所配模型名在服务端不存在 | 引入指数退避重试与模型自动降级机制，并增加本地模板兜底 |
| N5 | 第 10 天 | 安全评审实测发现"文件改名/删除类写法可绕过初版校验" | 扩充方法级黑名单与路径字面量校验，补充针对性测试用例 |
| N6 | 第 11 天 | 联调发现"模型加载后的对象在结果序列化中被破坏"导致推理失败 | 修正结果序列化策略，重建"训练—保存—加载—推理"全链路回归 |
| N7 | 第 12 天 | 联调发现报告仅显示机器意图标识、可读性不足 | 补充中文意图名称透传，报告可读性改善 |
| N8 | 第 14 天 | 全量回归测试 | 119 项自动化测试全部通过，交付物完成预演 |

## 五、工作量分配说明

| 角色 | 工作量占比 | 主要投入分布 |
| --- | --- | --- |
| 项目负责人兼后端集成 | 22% | 架构与接口设计 8%、集成与联调 10%、进度与评审 4% |
| Agent 核心开发 | 23% | 客户端封装 6%、提示词与意图 7%、生成-执行-修复闭环 7%、编排与历史 3% |
| 数据分析算法开发 | 22% | 统计与相关性 6%、时滞与异常 7%、机器学习 7%、图表与口径 2% |
| 前端交互开发 | 17% | 四个页签界面 10%、交互与可视化 5%、界面兜底 2% |
| 测试与文档交付 | 16% | 测试设计 6%、安全验证与回归 5%、文档与演示材料 5% |
| 合计 | 100% | — |

工作量分配遵循"复杂度匹配"原则：Agent 核心与算法层承担技术难点故占比最高；界面与文档工作量稳定但技术难度相对可控。每位成员在承担主职责之外，均参与他人模块的交叉评审，保证知识共享与交付质量。
