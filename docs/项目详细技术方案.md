# 项目详细技术方案

> 命题方：和利时企业命题 ｜ 项目名称：工业数据分析 Agent 系统 ｜ 文档类型：详细技术方案

## 一、总体设计思路

系统设计围绕三条主线展开：**能力标准化**（分析算法统一口径）、**执行安全化**（生成代码受控运行）、**交互自然化**（中文提问直出报告）。

整体采用严格的分层依赖：`analytics ← sandbox ← agent ← report ← app`。上层可依赖下层，下层禁止反向依赖，从而保证算法库可被独立测试与复用，沙箱可被独立审计，界面层可独立替换为其他前端框架。所有对外函数统一返回同一结构的结果包：

| 字段 | 含义 |
| --- | --- |
| `status` | 执行状态（success / error） |
| `data` | 业务数据（可序列化的指标、矩阵、明细） |
| `message` | 面向用户的中文说明 |
| `error` | 失败原因详情（成功时为 None） |
| `charts` | 本次产出的图表文件路径列表 |

统一结果包是"算法层—Agent 层—报告层—界面层"之间稳定的契约，也是全链路异常不外泄的技术基础：任何模块内部异常均被捕获并转换为 `error` 状态的结果包。

## 二、各模块详细设计

### 2.1 数据文件管理模块

- **存储与组织**：业务数据统一存放于 `data/` 目录，输出产物归档于 `output/`（含 `charts/`、`reports/`、`models/`）；
- **上传校验**：对上传内容做空值校验、大小上限校验（默认 200 MB）与扩展名校验，仅接受 CSV；文件名经规范化处理后写入数据目录，杜绝路径穿越；
- **编码自适应读取**：按 UTF-8 → GBK → UTF-8-BOM → 自动分隔符探测的顺序逐级尝试，兼容国内工业现场常见的 GBK 编码导出文件；
- **数据画像识别**：逐字段推断数据类型（数值 / 时间 / 布尔 / 分类 / 空列），统计缺失数量与缺失率、去重值数量与样例值；对字符串型时间列采用抽样解析（命中率 ≥ 90% 判定为时间字段），解决"时间列被读成文本"的常见问题；
- **删除保护**：删除操作严格限定在数据目录内、且必须是 `.csv` 文件，界面层需二次勾选确认。

### 2.2 数据分析算法库

五个模块各司其职，全部返回统一结果包：

| 模块 | 核心能力 |
| --- | --- |
| `basic_stats.py` | 字段画像识别、单列/多列描述性统计、频次统计、缺失值报告、分布直方图 |
| `correlation.py` | 相关性矩阵（含热力图）、强相关特征对挖掘、与目标变量相关性排序、散点拟合图 |
| `time_lag.py` | 互相关曲线计算、最优时滞识别、时滞结论生成、滞后时间换算、时滞曲线图 |
| `anomaly.py` | 3σ 异常检测（单列/多列）、MAD 稳健阈值对照、异常点明细、异常分布图 |
| `ml_models.py` | 三类回归模型训练、多指标评估、交叉验证、模型持久化与加载、批量推理、特征重要性 |

工程要点：随机种子固定保证结果可复现；数值列统一做安全数值化转换；样本量、方差、字段存在性等前置条件均给出明确的中文错误提示而非抛出异常；绘图采用 Agg 后端与中文字体自动适配（候选字体探测，避免中文乱码）。

### 2.3 Agent 核心逻辑模块

由三个子模块构成：

- **LLM 客户端**：封装 DeepSeek 接口（兼容 OpenAI 协议），支持代码模型与报告模型分离配置；具备指数退避重试、模型自动降级（当服务端返回"模型不存在"时自动改用备选模型）、双通道传输（官方 SDK 优先，缺失时回落标准库 HTTP 直连）；密钥脱敏展示，未配置密钥时以明确提示进入本地模板模式，不抛出异常；
- **代码生成器**：内置八大意图体系（基础统计、相关性、时滞、异常、建模、推理、缺失检查、数据总览）；LLM 模式下按系统提示词生成代码，先做静态安全校验，失败则将违规信息回灌模型自动修复（默认最多两轮）；同时内置与八大意图一一对应的本地模板代码，作为离线兜底，保证系统永远能产出可执行代码；
- **主控制器**：编排完整闭环——确定数据文件 → 读取数据并生成字段画像 → 解析分析意图 → 生成并执行代码 → 组织事实数据生成报告 → 归档历史记录；同时提供算法工具箱接口（可直接参数化调用统计算法，不依赖大模型）。

闭环中引入"生成—执行—修复"机制：若代码执行报错且来源于 LLM，则将标准错误回灌模型请求修复并重新执行，直至成功或达到修复轮数上限。

### 2.4 沙箱安全执行引擎

沙箱是本系统最关键的安全组件，设计详见第四节"安全沙箱机制详解"。

### 2.5 报告生成模块

- **事实优先原则**：先把执行结果整理为结构化"事实字典"（业务指标、执行状态、退出码、耗时、沙箱信息、代码文件路径、图表清单），再交由大模型撰写叙述性结论，从根本上避免模型编造数据；
- **双模板输出**：LLM 可用时生成高度贴合工艺语境的中文报告；不可用时由确定性模板渲染同结构报告，保证离线可用；
- **统一报告结构**：分析结论、关键指标表、图表说明、执行环境与安全检查、风险提示与优化建议五节；
- **双格式落盘**：Markdown 便于二次编辑，自包含 HTML 将图表以 Base64 内嵌，单文件即可分享与归档；
- **结论智能化**：按分析类型分别生成针对性结论文本（如时滞分析直接给出"某变量领先另一变量 N 个采样周期"的工艺表述，建模分析给出拟合优度与关键影响因素排序）。

### 2.6 Web 交互界面

基于 Streamlit 的纯 Python 实现，四个页签：

1. **数据文件管理**：上传、列表、数据画像、数据预览、缺失值分析、带确认的删除；
2. **自然语言分析**：示例问题一键填充、提问输入、模式开关（是否调用 LLM / 是否生成报告 / 是否展示代码）、执行流程时间线与沙箱执行详情（退出码、耗时、标准输出、结构化结果）；
3. **算法工具箱**：以表单方式参数化调用五类分析算法，覆盖无大模型场景；
4. **系统状态**：模型与密钥配置、沙箱策略、运行统计（数据集/图表/报告/模型/历史记录）、安全机制说明与分析历史。

界面层所有渲染逻辑均包裹异常处理，单点故障不会导致白屏。

## 三、核心算法原理

### 3.1 描述性统计

对数值序列 x₁,ṡ,xₙ：

- 均值 x̄=1/nΣxᵢ，样本标准差 s=√(1/(n-1)Σ(xᵢ-x̄)²)；
- 中位数、四分位数（Q₁、Q₃）与四分位距 IQR=Q₃-Q₁，对离群点天然稳健；
- 偏度衡量分布对称性，峰度衡量尾部厚度；变异系数 CV=s/|x̄| 用于跨量纲的波动性比较（工业上常用于判断控制回路的相对稳定性）；
- 同时输出缺失数量与缺失率，作为数据质量的前置判据。

### 3.2 Pearson 相关性分析

 r=(Σᵢ(xᵢ-x̄)(yᵢ-ȳ))/(√(Σᵢ(xᵢ-x̄)²)√(Σᵢ(yᵢ-ȳ)²)) 

r∈[-1,1]，绝对值越大线性相关越强。系统按 |r| 划分"极强（≥0.8）/强（≥0.6）/中等（≥0.4）/弱（≥0.2）/极弱"等级并标注正负方向，同时提供 Spearman（秩相关，抗非线性单调与离群）与 Kendall 方法。对多变量场景自动筛选 |r| 超过阈值的强相关特征对并按强度排序，为变量解耦与特征筛选提供依据。

### 3.3 时序互相关时滞分析

设两路时序为 xₜ、yₜ，定义滞后 l 的互相关系数：

 r(l)=corr(xₜ₋ₗ, yₜ), l∈[-L,L] 

- r(l) 在 l*=argmaxₗ |r(l)| 处取最优时滞；
- **符号约定**：l*>0 表示 x 领先 y，即 x 的变化经过 l* 个采样周期才在 y 上体现；l*<0 则相反；l*=0 表示同期相关最强；
- 若给出采样间隔 Δt，系统换算真实滞后时长 Δt*=l*·Δt（例如采样 5 分钟、滞后 4 步 = 20 分钟）；
- 工程含义：时滞即"调节提前量"，是串级控制整定、前馈补偿设计与质量预测的关键参数。

### 3.4 3σ 原则异常检测

假设数据近似服从正态分布，正常样本以 99.73% 概率落在 [μ-kσ, μ+kσ]（k 常取 3，可调 1~5），超出即判为异常，并支持单侧判定（仅高值或仅低值）。

为应对工业数据普遍存在的重尾与偏态问题，系统同时计算稳健阈值：

 median ± k×1.4826×MAD, MAD=median(|xᵢ-median(x)|) 

其中 1.4826 是正态分布下 MAD 到 σ 的一致化系数。两套阈值并列输出，工程人员可据此判断某点是"真实异常"还是"分布偏态导致的误报"。检测结果包含异常点数量、占比、上下界、逐点序号、偏离 σ 倍数与 Top-N 最偏离点。

### 3.5 随机森林回归建模

- **训练流程**：特征与目标字段解析 → 缺失样本剔除 → 按比例划分训练/测试集 → 模型拟合 → 指标评估 → 交叉验证 → 特征重要性提取 → 模型持久化；
- **算法原理**：对训练集做 Bootstrap 有放回抽样生成多棵决策树，每棵树在分裂时随机选取特征子集，最终取所有树预测值的平均。该机制通过"样本扰动 + 特征扰动"降低方差、抑制过拟合，且天然支持特征重要性输出，适合工业过程这种变量多、共线性强的场景；
- **评估指标**：MSE、RMSE、MAE、MAPE、测试集 R² 与训练集 R²（用于识别过拟合）、K 折交叉验证的 R² 均值与标准差（衡量泛化稳定性）；
   R² = 1-(Σ(yᵢ-ŷᵢ)²)/(Σ(yᵢ-ȳ)²), RMSE=√(1/nΣ(yᵢ-ŷᵢ)²) 
- **工程增强**：可选特征标准化（以流水线形式与模型一并保存，杜绝推理期变换不一致）；模型以 joblib 持久化并附带元数据文件（记录目标列、特征列顺序、超参数与评估指标），推理时自动按元数据对齐特征，避免"训练—推理错位"；同时提供特征重要性与回归系数排序，用于工艺机理解释。

## 四、安全沙箱机制详解

大模型生成代码的本质是"不可信输入"，沙箱从五个维度构建防御。

### 4.1 进程级隔离

- 生成代码落盘为独立脚本，由子进程以 **`python -I -X utf8 <script>`** 方式执行，**绝不使用 `exec()`**；隔离模式使子进程忽略 PYTHONPATH 与用户级 site-packages 污染；
- 每次运行创建独立的空工作目录（`output/.sandbox/run_<时间戳>_<随机串>`）并作为子进程 CWD，运行痕迹可按次追溯；
- 结果通过约定的 JSON 文件回传（生成代码须调用结果输出函数），避免通过标准输出解析造成的歧义；
- 历史运行目录按上限自动清理，防止磁盘无限增长。

### 4.2 AST 白名单校验

在代码执行前以抽象语法树方式做静态审计：

- **导入白名单**：仅允许 pandas、numpy、scipy、sklearn、matplotlib、seaborn、joblib、项目自带算法库及 math/statistics/json/datetime/re/itertools/functools/collections/pathlib 等标准库；`os`、`sys`、`subprocess`、`socket`、`shutil`、`importlib`、`pickle`、`ctypes`、`glob` 等系统级/网络级模块一律拒绝；
- **危险函数禁用**：`exec`、`eval`、`compile`、`__import__`、`open`、`input`、`getattr`、`setattr`、`globals`、`locals` 等；
- **魔术属性拦截**：禁止访问任何双下划线属性，切断 `().__class__.__bases__` 一类经典逃逸链；
- **资源耗尽防护**：禁止 `while True` 无界循环与超大内存分配写法，禁止 `assert`；
- **正则冗余筛查**：对系统模块导入、子进程调用、网络访问、外部命令解释器、超大内存分配等模式做第二道快速筛查，与 AST 校验互为补充。

校验不通过时给出"第 N 行 + 违规原因"的逐条明细，既可直接阻断执行，也可作为代码自修复的输入。

### 4.3 目录权限限制

- **路径字面量约束**：代码中出现的绝对路径必须落在 `data/` 或 `output/` 之内（相对路径按运行目录解析后同样校验），越界一律拒绝；
- **破坏性操作封锁**：禁止文件系统枚举（glob / rglob / listdir / scandir / walk / iterdir）与删除改名（unlink / rmtree / rmdir / chmod / rename 等）；
- **读写收敛**：统一通过数据读取函数、图表保存函数与模型持久化函数完成文件操作，业务数据目录在语义上保持只读；
- **敏感变量剥离**：子进程环境变量采用白名单透传（仅 PATH、SYSTEMROOT、TEMP 等系统必需项），`DEEPSEEK_API_KEY` 等敏感配置**不会**传入子进程，防止密钥经生成代码外泄；HOME 与临时目录一并重定向到本次运行目录，避免污染用户配置。

### 4.4 执行超时控制

- 默认单次执行超时 60 秒（可通过环境变量与界面滑块调整），超时后强制终止**整个进程树**：Windows 使用 `taskkill /F /T`，POSIX 使用 `os.killpg` 发送 SIGKILL，杜绝子进程遗留；
- POSIX 平台额外通过资源限制机制约束地址空间、CPU 时间与单文件写入大小，实现资源维度的硬约束；
- 标准输出与标准错误按字符数上限截断，防止异常日志或海量打印引发内存膨胀。

### 4.5 残余风险与生产建议

子进程与主进程同属一个操作系统账户，**subprocess 并非强隔离边界**。若攻击者能够完全控制生成代码，理论上仍可能借助合法依赖库的未知漏洞发起攻击。因此生产环境建议叠加：以低权限专用账户运行、将沙箱置于 Docker/gVisor 等容器内、关闭容器网络出口、对输出目录设置独立磁盘配额。本系统的五道防线可作为容器化之前的第一层防护，风险边界明确且可验证。

## 五、系统技术优势与亮点

1. **安全可验证**：五道防线均有对应的测试用例覆盖（危险代码拦截、路径越界、文件删除、无界循环、超时终止、密钥隔离），安全能力不是"设计声明"而是"测试事实"；
2. **离线可运行**：规则化意图解析 + 本地模板代码 + 模板报告三重兜底，无外网、无 API 密钥也能完整演示与使用；
3. **结果可复现**：固定随机种子、统一评估口径、模型附带元数据，杜绝"一次一个样"；
4. **工程健壮性**：统一结果包契约 + 全链路异常兜底 + 数据编码自适应 + 中文字体自适应，面向真实工业数据而非理想样本；
5. **可扩展架构**：算法层与智能体层解耦，新增分析能力只需在算法层扩展并注册意图，界面与安全机制无需改动；
6. **工业语义贴合**：时滞结论自动换算工艺时间并给出调节提前量建议，异常检测提供稳健阈值对照，建模输出特征重要性用于机理印证，处处体现流程工业语境。
